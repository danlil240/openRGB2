# OpenRGB2 UI first-look report — 2026-09-28

## Scope and observed state

Reviewed the packaged `openrgb2-ui.exe` in `build/package/OpenRGB2-0.1.0-win64/` using the Windows UI, at approximately 1647 × 771 and 3440 × 1392 window sizes. Repository revision: `22632a2`; the packaged UI executable is dated 2026-09-28 01:40. The engine and backend were running and connected. Dashboard reported 7/7 controllers connected, Live effects on device, no applied scene, and no frame data. Diagnostics reported the engine running, backend protocol v4 connected, and no measured output rate. Those empty/unknown states are consistent with no scene being loaded and are not counted as defects below.

I navigated all five views and scrolled through their content. I selected Spectrum Cycle in a fresh UI window to expose its controls, without saving it or sending a scene to the engine. I did not run LED identification, alter reactive capture, export diagnostics, or change hardware playback. The observations below are visual and interaction findings; hardware output, scene persistence, and modal workflows remain unverified.

### Interaction anomaly to reproduce separately

The already-running UI window initially displayed Lighting with unsaved changes and a “scene name is empty” refusal. Repeated navigation clicks, scrolling, and Tab produced no visible change, although Windows reported the process as responding. A second UI window launched from the same packaged executable connected to the engine and responded normally. After closing that temporary window, a further navigation click in the original window still had no visible effect. This could be an application-specific stalled window, a focus/input routing issue, or an automation artifact; it is **not yet a confirmed product bug**. Reproduce with ordinary mouse input and inspect the original window before assigning a severity. The second window increased the diagnostic IPC session count to 2 while it was open, as expected.

## Triage suggestion

Investigate `Card.qml` sizing together with the parent `Column`/`RowLayout` width and implicit-height bindings. UI-01, UI-02, and UI-03 may share a layout mechanism, but that is a source-review hypothesis, not a confirmed root cause. Recheck all five views at normal and maximized sizes after any fix; then repeat the edit/save and playback-mode flows with a noncritical scene and hardware test window.
